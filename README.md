# 밤의 기록 — 6~8인 머더미스터리 베타
진행자 없이 함께 플레이하는 모바일 대응 웹 앱입니다. 첫 시나리오는 가상 기업 백야전자의 **마지막 결재**입니다. 기존 이야기의 문서·독살·과거 은폐 구조를 각색했으며, 실제 이름 대신 참가자가 입력한 이름을 역할에 연결합니다.

## 바로 실행
Python 3.12 이상을 설치한 뒤 압축을 풀고 프로젝트 폴더에서 실행합니다.

```bash
python3 server.py
```

PC에서 http://localhost:8000 에 접속합니다. 같은 Wi-Fi의 휴대폰은 서버 PC의 LAN 주소(예: http://192.168.0.10:8000)로 접속합니다. PC 방화벽에서 해당 포트를 허용해야 할 수 있습니다. 휴대폰의 localhost는 PC가 아닙니다.

혼자 여러 명 테스트할 때는 브라우저 프로필을 분리하세요. 같은 브라우저 저장소에는 하나의 개인 입장권만 저장됩니다. 각 참가자는 본인 기기로 접속하는 것이 기본입니다.

## 플레이 흐름
1. 방 생성: 이름, 6/7/8명, 빠르게/여유롭게 선택.
2. 초대 링크 또는 코드를 친구에게 공유.
3. 공개 시나리오 소개와 역할 소개를 읽고 각자 캐릭터 선택.
4. 정원이 모두 입장하고 준비하면 자동 시작.
5. 캐릭터북 → 조사 3라운드 → 최종 추리 → 공동 엔딩.
6. 종료 후 참가 여부와 관계없이 8명 모두의 캐릭터북과 전체 단서 열람.

읽기·조사 단계는 전원이 다음 단계에 동의하거나 시간이 끝나면 넘어갑니다. 최종 추리는 전원 제출 또는 시간 종료 시 집계합니다. 중간 이탈자가 있어도 타이머로 계속 진행합니다. 시작 후 참가자 교체는 지원하지 않습니다.

## 포함한 기능
- 공개 채팅과 1:1 귓속말. 약 1.8초 간격 서버 조회 방식이며 음성/영상은 없습니다.
- 6개 필수 역할과 2개 선택 역할. 미선택 역할은 참고인으로 남고 그 단서도 조사할 수 있습니다.
- 조사 토큰: 라운드마다 1개씩 지급, 미사용분 누적, 자기 단서 열람은 무료.
- 타인 단서는 선착순 한 명이 조사하고 조사자 또는 소유자가 공개 공유 가능.
- 핵심 증거 자동 공개: 선택 역할의 부재나 단서 비공개만으로 정답 경로가 사라지지 않도록 구성.
- 객관식 4문항 자동 채점, 자유 서술 메모, 집계 결과에 따른 엔딩.
- 제출·조사 확인은 페이지 내부 창 사용.
- SQLite 저장으로 서버 재시작 후 복구. 방은 생성 후 7일에 자동 삭제.
- 개인 입장권으로 재접속. 대기실에서 복구 정보를 복사해 보관할 수 있습니다. 개인 입장권은 타인에게 공유하지 마세요.
- 반응형 웹 및 웹 앱 manifest. 오프라인 실행은 지원하지 않습니다.

## 원격 플레이 배포
서로 다른 장소에서 접속하려면 인터넷에서 접근 가능한 서버와 HTTPS 주소가 필요합니다. 이 프로젝트는 서버에서 비밀 정보와 진행 상태를 처리하므로 GitHub Pages에 파일만 올려서는 동작하지 않습니다.

Linux 서버/컨테이너에서 다음 설정을 사용하세요.

```bash
pip install -r requirements-production.txt
gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 8 server:application
```

- PUBLIC_ORIGIN: 최종 접속 주소. 예: https://game.example.com (끝에 / 없이).
- DB_PATH: 영속 저장소 안의 SQLite 경로. 기본값 data/game.sqlite3.
- HTTPS 역방향 프록시가 같은 도메인의 정적 화면과 /api 요청을 이 서버로 전달하게 설정합니다.
- 서버 복제본 1개, worker 1개로 시작하세요. 현재 스케줄러와 요청 제한기는 단일 프로세스를 전제로 합니다.
- 컨테이너 사용 시 아래 compose 예시가 데이터 볼륨을 유지합니다. 기본 노출은 서버의 127.0.0.1:8000이므로 앞단 프록시가 필요합니다.
- 백업에는 SQLite 본체와 WAL의 일관성이 필요합니다. 서버를 멈춘 상태로 데이터 폴더를 백업하거나 SQLite backup API를 사용하세요.
- 배포 환경의 디스크가 임시 저장소라면 재배포 때 게임이 소실됩니다. 영속 볼륨을 연결해야 합니다.
- 프록시 뒤에서는 요청 제한이 프록시 주소에 합산될 수 있습니다. 이 버전은 소규모 베타용이며 여러 방 규모의 공개 운영 전 부하 측정과 신뢰 프록시 설정 개선이 필요합니다.

Docker 선택 실행:
```bash
PUBLIC_ORIGIN=https://game.example.com docker compose up --build -d
```

Gunicorn 옵션 참고: https://gunicorn.org/reference/settings/
실제 공개 배포는 수행하지 않았고, 클라우드 계정/도메인 설정은 포함하지 않습니다.

## 코드 구조
| 파일 | 담당 |
|---|---|
| scenario.py | 역할, 비공개 사연, 단서, 공통 증거, 정답 |
| engine.py | 권한, 조사, 단계 전환, 채점, 엔딩, DB |
| server.py | HTTP API, 정적 파일 허용 목록, 요청 제한 |
| static/app.js | 화면, 채팅, 제출, 입장권 저장 |
| static/style.css | PC/모바일 레이아웃 |
| tests/test_game.py | 20개 자동 테스트 |
| docs/SCENARIOS.md | 시나리오 추가와 가변 요소 설계 |

## 검증과 남은 범위
```bash
python3 -m unittest discover -s tests -v
node --check static/app.js
```

6·7·8인 완료, 역할 충돌, 단서 동시 조사, 비공개 정보/귓속말 접근, 제출 검증, 타이머, 서버 재시작 상태 보존, 엔딩 열람, HTTP 경로를 테스트했습니다. 실제 iOS/Android 브라우저 및 화면 레이아웃 검증은 아직 수행하지 않았습니다. 배포 구성도 실제 클라우드에서 검증하지 않았습니다.

현재는 완성 시나리오 1편입니다. 4~5편의 완성 원고나 시나리오 선택 메뉴, 범인 무작위 변경은 아직 없습니다. 등장인물 배정/참가자 이름/선택 역할/공개 방식/투표 결과는 가변이지만 사건의 진실은 고정입니다.

공개 서비스의 결제, 회원 관리, 운영자 관리 화면, 신고/차단, 접속자 대규모 부하 대응은 후속 범위입니다. 실명 대신 닉네임을 권장하며, 방 코드와 개인 입장권은 분리합니다. 서버 운영자는 DB에 저장된 게임 기록을 읽을 수 있습니다. 단서 난이도와 대화 시간은 실제 6~8인 플레이로 조정해야 합니다.
