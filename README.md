# 밤의 기록 — 6~8인 머더미스터리 베타
진행자 없이 함께 플레이하는 모바일 대응 웹 앱입니다. 첫 시나리오는 가상 기업 백야전자의 **마지막 결재**입니다. 각 인물은 **캐릭터 이름**(예: 한서진)과 직함으로 표시되고, 플레이어가 입력한 실제 이름은 작게 함께 표시되어 친구끼리 구분됩니다.

## 바로 실행 (로컬)
Python 3.12 이상이 필요합니다. 추가 패키지는 없습니다.

```bash
python3 server.py
```

PC에서 http://localhost:8000 에 접속합니다. 같은 Wi-Fi의 휴대폰은 서버 PC의 LAN 주소로 접속합니다. 로컬에서는 SQLite 파일(`data/game.sqlite3`)에 저장하고, 시간 진행과 만료 정리는 서버 안의 스케줄러가 처리합니다.

> 브라우저 알림과 서비스 워커는 HTTPS 또는 localhost 에서만 동작합니다. LAN 주소(http)에서는 앱 안 팝업만 동작합니다.

## Vercel 배포
Vercel 함수는 요청마다 다른 인스턴스에서 실행되고 파일이 유지되지 않으므로 SQLite 파일을 쓸 수 없습니다. 그래서 **Redis REST 저장소**(Upstash Redis)를 연결합니다. 코드는 환경변수로 저장소를 자동 선택합니다.

1. 이 폴더를 Git 저장소로 올리고 Vercel에서 **Add New → Project**로 가져옵니다. Framework Preset은 **Other**, Build/Output 설정은 비워 둡니다.
2. 프로젝트의 **Storage** 탭(또는 Marketplace)에서 **Upstash Redis**를 만들어 프로젝트에 연결합니다. 연결하면 `KV_REST_API_URL`, `KV_REST_API_TOKEN`(또는 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`)이 자동으로 추가됩니다. 수동으로 넣어도 됩니다.
3. 배포합니다. 배포 주소 뒤에 `/health`를 열어 `{"ok": true}`가 나오는지 확인합니다.
4. 저장소 연결이 빠지면 방 만들기 때 “저장소가 연결되지 않았습니다” 안내가 표시됩니다.

선택 환경변수: `PUBLIC_ORIGIN`(커스텀 도메인을 쓸 때 `https://game.example.com`). 비워 두면 요청의 Host와 Origin이 같은지만 확인합니다.

CLI로 미리 확인하려면 `vercel dev` 를 사용하세요(위 환경변수 필요). 로컬 개발은 `python3 server.py` 가 더 간단합니다.

### Vercel 구조와 동작 방식
| 구성 | 설명 |
|---|---|
| `public/` | 화면, 스크립트, 서체. Vercel CDN이 직접 제공합니다. |
| `api/index.py` | 서버리스 진입점. `server.py`의 WSGI 앱을 `app`으로 노출합니다. |
| `vercel.json` | `/api/*`, `/health`, `/img/*`를 함수로 연결하고 보안 헤더(CSP 등)를 지정합니다. |
| `store.py` | 방 저장소. 로컬은 SQLite, Vercel은 Redis REST. 낙관적 잠금(rev)으로 동시 저장 충돌을 막습니다. |

- **시간 진행**: 서버리스에는 상시 스레드가 없으므로 요청이 올 때마다 마감 시간을 계산해 단계를 넘깁니다. 모두 접속을 끊은 방은 다음 접속 때 한 단계씩 따라잡습니다.
- **저장소 요청 절감**: 상태 조회는 상태가 바뀌었거나 접속 표시가 8초 이상 오래됐을 때만 저장합니다. 6명이 50분 플레이하면 Redis 명령은 대략 1만 건 안팎입니다. 폴링은 2.5초(백그라운드 탭 4초) 간격입니다.
- **방 수명**: 마지막 저장 후 7일이 지나면 Redis TTL로 자동 삭제됩니다.
- **한도**: 방 하나는 JSON 한 덩어리로 저장되며 메시지 2,400개 제한이 있습니다. Upstash 무료 요금제의 요청 크기·월 명령 수 한도를 확인하세요.
- **요청 제한기**는 함수 인스턴스별 메모리 기준이라 여러 인스턴스에서는 느슨합니다. 공개 운영 전에는 Vercel Firewall의 Rate Limiting 사용을 권장합니다.
- **이미지**: `/img/photos/<id>` 처럼 확장자가 없는 주소는 함수가 `public/img/`에서 찾아 응답합니다. 이미지를 추가하면 다시 배포해야 합니다.

## 플레이 흐름
1. 처음 접속하면 **게임 설명(튜토리얼)** 이 먼저 나옵니다. 시작 화면과 대기실에서 다시 볼 수 있습니다.
2. 방 생성: 이름, 인원, 속도를 선택하면 대기실 맨 위에 **초대 코드**와 **코드 복사 / 초대 링크 복사 / 공유하기** 버튼이 나타납니다.
3. 캐릭터(이름·직함·소개)를 고르고 준비 완료. 정원이 차고 모두 준비하면 자동 시작.
4. 캐릭터북 → 현장 조사 → 엇갈린 증언 → 마지막 증거 → 최종 추리 → 엔딩.
5. 단계가 바뀌면 **이번 단계에서 할 일** 팝업이 뜨고, 해당 탭이 강조(NEW 표시와 깜빡임)됩니다. 화면에는 항상 “지금 할 일” 카드와 “다음 단계 동의” 설명, 누가 동의했는지가 표시됩니다.
6. 엔딩은 **연출 시퀀스**(판결 공개 → 범인 검거 장면 → 사건의 진상과 시간순 기록 → 각자의 밤 → 그 후)로 진행되고, 이후 엔딩 탭에서 전체 기록을 다시 볼 수 있습니다.

## 단서와 증거
- **조사 탭**: 내 단서(무료)와 다른 인물의 봉인된 단서(토큰 1개). 단서 카드 상단 리본으로 구분합니다: 초록 = 내 단서, 황색 = 내가 조사한 단서, 보라 = 모두에게 공개된 단서, 남색 = 나에게만 공개된 단서.
- **단서 탭**: 공개된 단서 모음(나에게만 공개된 것 / 모두에게 공개된 것 / 내가 일부에게 공개한 것).
- **공용 증거 탭**: 단계마다 시스템이 모두에게 자동 공개하는 현장 자료. 인물별 단서와 별개입니다.
- **공개하기**: 단서를 모두에게, 또는 체크한 사람에게만 공개합니다. 선택하지 않은 사람에게는 내용이 보이지 않지만 “누가 누구에게 공개했는지”는 알림 팝업으로 전달됩니다(채팅에는 남기지 않습니다).

## 알림
- 새 채팅·귓속말·단서 공개가 오면 앱 안 팝업과 소리·진동이 나옵니다.
- 알림을 허용하면 다른 탭이나 앱에 있을 때도 브라우저 알림이 뜹니다(`public/sw.js` 서비스 워커 사용). 서버가 폴링 방식이라 브라우저를 완전히 닫으면 알림은 오지 않습니다. iPhone은 홈 화면에 추가한 웹 앱에서만 알림을 받을 수 있습니다.

## 개발 규칙
1. **글 표시**: 모든 글은 `fmt()`/`P()`로 출력합니다. 문장이 끝나면 줄을 바꾸고(따옴표 안의 마침표는 끊지 않음), “21:40 …”처럼 시간으로 시작하는 문장은 시간 순서로 정렬해 시간표 형태로 보여줍니다. 시나리오 글을 쓸 때는 문장을 짧게 끊고, 시간 순서가 있는 내용은 문장 맨 앞에 시간을 적습니다.
2. **색 대비**: 배경색이 있는 배지·태그·버튼은 글씨색을 반드시 명시합니다. 상속에 기대지 않습니다. (과거에 `color: unset` 예외 목록 때문에 검은 꼬리표에 검은 글씨가 되는 문제가 있었습니다.)
3. **CSP**: HTML의 `style="…"` 속성은 CSP로 차단됩니다. 값이 동적이면 `data-*` 속성에 담고 스크립트에서 `element.style.setProperty()`로 적용합니다(엔딩 연출의 `data-d` 참고).
4. **이름**: 이야기 글에는 `{planner}`(캐릭터 이름), `{planner:n}`(이름), `{planner:t}`(직함), `{planner:p}`(플레이어 이름) 토큰을 씁니다. 뒤따르는 조사(이/가, 은/는, 을/를, 와/과, (으)로, 이다)는 받침에 맞게 자동 교정됩니다. 캐릭터 이름은 `scenario.py`의 `CHAR_NAMES`에서 바꿉니다. 리테일 기획자의 비밀(강도윤의 자녀)이 드러나지 않도록 성을 같게 하지 마세요.
5. **엔딩 원고**: `scenario.py`의 `ENDING`(등급별 도입·검거 장면·후일담·마무리), `FATE`(인물별 후일담), `ABSENT`(참고인), `NIGHT_TIMELINE`(밤의 시간순 기록)을 수정합니다.

## 검증
```bash
python3 -m unittest discover -s tests -v
node --check public/app.js
```

`test_store.py`는 실제 Upstash 대신 같은 REST 프로토콜을 흉내 내는 가짜 서버로 방 생성·입장·역할 선택, 동시 저장 충돌 재시도, 상태 조회 시 저장 최소화, 저장소 오류 안내를 검증합니다. Redis의 Lua 스크립트 자체는 가짜 서버가 같은 의미로 흉내 낸 것이므로, 배포 후 실제 환경에서 한 번 플레이해 확인하세요. 실제 Vercel 배포와 iOS/Android 실기기 검증은 수행하지 않았습니다.

현재는 완성 시나리오 1편입니다. 사건의 진실은 고정이며, 참가자 이름·선택 역할·공개 방식·투표 결과에 따라 엔딩이 달라집니다. 실명 대신 닉네임을 권장합니다. 서버 운영자는 저장소에 보관된 게임 기록을 읽을 수 있습니다.

## 화면 테마와 이미지
- 서체(Noto Serif KR, IBM Plex Mono)는 `public/fonts`에 포함되어 외부 연결 없이 로드됩니다.
- **테마**: `scenario.py` 끝의 `THEME`을 `noir`(기본) / `school` / `romance` / `medieval` 중 하나로 지정합니다. 미리보기는 주소 뒤에 `?theme=school` 처럼 붙입니다.
- **표지 도장 / 카드 띠 문구**: `STAMP`(비우면 도장 숨김), `STRIP`(역할 카드 상단 띠 문구).
- **이미지**: 파일이 없으면 인물 사진은 실루엣으로 표시되고, 단서·증거 카드의 이미지 칸은 접힙니다. 파일을 넣으면 자동으로 채워지며 확장자는 jpg, jpeg, png, webp 중 아무거나 됩니다. 파일명은 확장자를 뺀 id입니다.

| 위치 | 폴더 | 파일명 예시 |
|---|---|---|
| 캐릭터 사진 | `public/img/photos/` | `planner.jpg` (역할 id) |
| 단서 이미지 | `public/img/clues/` | `planner-1.jpg` (단서 id) |
| 공용 증거 이미지 | `public/img/evidence/` | `e1.jpg` (증거 id) |

권장 크기: 캐릭터 사진 3:4(예: 600×800), 단서·증거 이미지 16:10(예: 1280×800). 파일 하나는 300KB 이하를 권장합니다.
