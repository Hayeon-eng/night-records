# 시나리오 확장 규칙
이 문서는 제작자용입니다. 플레이어에게 배포하는 static 폴더 안에 넣지 마세요.

## 현재 구현
마지막 결재 1편의 사건 진실은 고정입니다. 이름은 역할 ID에 매핑되며, 역할 배정과 플레이어의 조사·공유·투표 행동이 바뀝니다. 정답·캐릭터북·미공개 단서는 서버에만 있고 권한에 맞는 부분만 브라우저로 전달됩니다.

6명은 필수 역할 6개, 7명은 필수 6개와 선택 1개, 8명은 전체 역할을 사용합니다. 선택 역할이 없어도 해당 인물은 참고인으로 남고 그 단서가 사라지지 않습니다. 핵심 진상은 단계별 공통 증거에도 연결됩니다.

## 안전하게 바꿀 수 있는 것
- 참가자 이름: 역할 ID를 유지하고 표시 문자열만 교체.
- 분위기, 가상 회사/장소 이름: 시간표와 접근 경로가 같은 경우.
- 선택 역할: 핵심 증거를 필수 역할/공통 증거로도 확인 가능하게 유지.
- 엔딩 정서: 범인 지목 여부와 과거 사건 규명 여부에 맞춰 문장 선택.

범인, 범행 방식, 사망 시각, 알리바이를 독립적으로 무작위 선택하면 모순이 생깁니다. 이를 바꾸려면 서로 맞는 전체 변형 패키지를 제작해야 합니다.

## 4~5편으로 확장하는 순서
1. scenario.py를 참고해 시나리오별 데이터 모듈 작성.
2. 서버에 scenario_id → 모듈 레지스트리 도입.
3. 방 생성 때 scenario_id와 고정된 variant_id 저장.
4. engine.py의 전역 S 참조를 방에 저장된 시나리오를 불러오는 방식으로 전환.
5. 시나리오별 필수 역할, 질문, 정답, 엔딩 판정을 연결.
6. 공개 카탈로그와 방 만들기 화면에 선택 메뉴 추가.
7. 모든 시나리오/변형을 6·7·8명으로 끝까지 돌려 검증.

현재 엔진은 진행 로직과 데이터가 분리되어 있지만 S를 전역으로 참조하므로 여러 시나리오 동시 선택을 바로 지원하지는 않습니다.

## 추리 보존 검증
scenario.py의 DEPENDENCIES는 정답에 필요한 공개 증거/단서를 표시합니다. 기존 자동 테스트는 ID 존재와 진행·권한을 검증합니다. 문장 사이의 인과관계나 추리 난이도가 옳은지는 사람의 검토가 필요합니다.

시나리오마다 다음을 확인하세요.
- 동기, 기회, 수단, 사망 원인이 최소 두 경로로 입증되는가.
- 무고한 인물의 수상한 행동도 설명되고 배제 가능한가.
- 선택 역할이 없거나 누군가 비공개 단서를 숨겨도 최종 결론이 가능한가.
- 동률/오지목/미제출 엔딩이 특정 인물을 범인으로 단정하지 않는가.
- 선택한 정답으로만 점수를 계산하며 자유 서술을 거짓으로 자동 채점하지 않는가.
- 범인이 정답을 제출해도 본인의 투표 하나로 집단 판단이 뒤집히지 않는가.

## 현재 엔딩 조건
객관식 4문항 각 1점, 미제출자는 0점으로 전체 인원 평균에 포함합니다.
- 범인 지목 최다 득표가 단독으로 진범: 검거.
- 동률/무투표: 집단 지목 미확정.
- 단독 최다 득표가 다른 인물: 오지목.
- 검거 + 평균 3.5 이상 + 과거 사건 정답 과반: perfect.
- 검거 + 평균 2.5 이상: true.
- 그 외 검거: normal.
- 진범 검거 실패: bad.

결과는 서버에서 한 번 확정한 뒤 전원이 동일한 공동 결과를 봅니다. 개인 점수/개인 후일담이 함께 표시되며, 이후 모든 캐릭터북과 단서를 열람합니다.
